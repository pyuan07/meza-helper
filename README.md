A companion app for **Pokémon Mezastar** players — keep your trainer passes on your phone, track
which tags you've collected, and look up support tags and special moves without digging through
wiki pages at the arcade.

Built with Flutter. Runs on Android, iOS, web (as an installable PWA), and desktop.

## Features

### 🎫 Trainer Pass
Store multiple trainer IDs and display them as scannable QR codes at the machine. The app boosts
screen brightness automatically while a code is on screen so the scanner reads it first time.
Add trainers manually, or import one from a screenshot.

### 📇 Tag Dex
Browse the tag catalogue across game versions and track your collection. Filter by ownership
(*My Collection* vs *Missing*), plus advanced filters for narrowing down what you're hunting.
Includes a dedicated **Tags Tower** view.

### ⚡ Z-Moves
Quick reference for special and Z-move data, so you can check a move mid-session.

### 🛠️ Support
Reference for support tags and their moves — Mega Charizard X, Mega Gardevoir, Keldeo, Duraludon
and more — with region-aware listings.

### ⚙️ Settings
- **Languages:** English, 中文
- **Regions:** Singapore 🇸🇬, Malaysia 🇲🇾

Everything is stored locally on your device with Hive. **No account, no server, no tracking** —
the app works fully offline.

## Getting Started

### Prerequisites

- [Flutter SDK](https://docs.flutter.dev/get-started/install) with Dart SDK **3.2.0+**
- Android Studio / Xcode for native builds, or just a browser for web

Verify your setup:

```bash
flutter doctor
```

### Run

```bash
git clone https://github.com/pyuan07/meza-helper.git
cd meza-helper

flutter pub get
flutter run
```

Target a specific platform:

```bash
flutter run -d chrome     # web
flutter run -d android    # android device/emulator
flutter run -d macos      # desktop
```

### Code Generation

The project uses `hive_generator` and `riverpod_generator`. After changing a model or a provider
annotation, regenerate the `.g.dart` files:

```bash
dart run build_runner build --delete-conflicting-outputs
```

Or watch continuously while developing:

```bash
dart run build_runner watch --delete-conflicting-outputs
```

### Build for Release

```bash
flutter build apk --release          # Android APK
flutter build appbundle --release    # Android App Bundle (Play Store)
flutter build ios --release          # iOS
flutter build web --release          # Web / PWA
```

App icons are generated by `flutter_launcher_icons`:

```bash
dart run flutter_launcher_icons
```

## Project Structure

```
lib/
├── main.dart                  App entry, theming, bottom-nav scaffold
├── core/                      Cross-cutting concerns
│   ├── theme.dart             Colors and Material theme
│   ├── result.dart            Result type for error handling
│   ├── error_handler.dart     Centralized error handling
│   ├── responsive.dart        Breakpoints and layout helpers
│   ├── platform_utils.dart    Platform detection
│   └── pwa/                   Web update detection and prompts
├── features/                  One folder per feature
│   ├── trainer_pass/          Trainer storage, QR display, screenshot import
│   ├── tag_dex/               Tag catalogue, filters, Tags Tower
│   ├── z_moves/               Z-move reference
│   ├── support/               Support tag reference
│   ├── settings/              Language and region preferences
│   ├── home/                  Home screen
│   └── others/                Overflow menu
├── models/                    Hive-backed data models (+ generated .g.dart)
├── providers/                 Riverpod providers
├── services/                  Storage service
├── shared/widgets/            Reusable UI (glass containers, empty states, type icons)
└── utils/web_qr/              Conditional web QR implementation
```

### Architecture

- **State management:** [Riverpod](https://riverpod.dev/) with code generation
- **Local storage:** [Hive](https://docs.hivedb.dev/) — models are Hive-annotated and boxes are
  opened at startup in `main.dart`
- **Feature-first layout:** each feature owns its screens, widgets and `data/` sources
- **Data sources:** tag data is split between a static source (bundled catalogue) and a local
  source (the user's collection)
- **Conditional imports:** web-only code (`web_qr_web.dart`) is swapped in via a stub so the same
  codebase builds everywhere
